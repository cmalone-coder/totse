Re: FC7 Upgrade
If you're unfamiliar with basic system administration it is probably not a good idea to upgrade.

Fedora 7 has a new kernel which uses libata for PATA disks, so what used to be hd[a-d] is now sd[a-d] and would require you to modify your fstab and possibly recreate your initramfs afterwards with mkinitrd.

If this isn't an issue, package sets are not a big concern.
You can upgrade using Yum or with the DVD or boot.iso over HTTP.

Quote:
Originally Posted by deus-redux

That's odd for it to just stop, how long do you think you waited when it was stopped before you did anything else?

Quote:
I ran yum again to find it complaining about yum, dbus, and rpm Python modules not being installed, so I downloaded and installed them manually from the F7 repo.
That seems very strange, in the course of yum doing a release upgrade to another release, while packages are being upgraded Yum doesn't reload anything, definitely something to look into and report if we determine it is a bug in a package or some other problem that only occurs when updating specific packages.
Quote:
That seemed to enable me to start yum without it barfing, but now...
And it just hangs there.
Same thing happens with yum update
After making sure yum-updatesd service is off or simply not installed and that no Yum processes are running, try this:
Code:
rm -rf /var/run/yum.pid
rm -rf /var/lib/rpm/__db.*
yum clean all
yum update
If you find it is still hanging, try:
Code:
rm -rf /var/lib/rpm/__db.*
rpm --rebuilddb
Do not interrupt that process.

What can happen is the RPM database lock files may be left by a killed process or some other reason.. such as a RPM %post script which happen to wind up in a deadlock or possibly was killed for whatever reason. It isn't common now but it can still happen, it used to be more common in earlier versions of Fedora since RPM has been going through heavy development.

Regardless if it fixes it or not, could you also post your /var/log/yum.log file here?
