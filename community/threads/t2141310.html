I wouldn't use Ubuntu Server. It installs a lot of things that you don't need for a server that has a specific purpose. For servers that run Gnu, I nearly always use Gentoo.

For this you're asking for two things -- first, a fileserver. A server that serves files. You can do this in a lot of ways, but the best things to do in this case (music and porn) are as follows. (all of the applications mentioned are in the Gentoo portage tree.)

  • Emerge mt-daapd and configure it to point at your music, then set it to start at boot. This runs a daap daemon (hence daapd), daap being the protocol that allows LAN computers running iTunes to "share" libraries. Most music players support daap, so it'll let you and your dorm listen to the music on the server without any extra configuration.
  • Install and configure Samba shares for the music and porn and whatever else you want. You can have an "uploads" directory in each that's world-writeable, allowing anyone to dump anything into there. You can pick through it and sort it out later (for the music one, it'd be fun to write a script that auto-grouped files into directories based on relevant tags). You could also have a README file that described how to get (more) access, that could contain the "see room 101" info.
  • Samba is okay, but it's fundamentally weak. For really powerful copying, I recommend (and this entire bullet is optional) setting up an rsync daemon. This will enable your dormmates to "sync" files and folders to and from your server, and uses the powerful rsync protocol to make things screaming fast. They could keep a directory of their music and sync it to your server, and after the first sync, they'd only be updating the parts of the files that were changed. They could also keep a mirror of your server locally if they needed faster access or wanted to back it up, and again, after the first run of rsync, they'd only be downloading the changed parts. You could do this with only samba, but it would be more of a hassle to configure clientside.
  • I advise you against setting up a "web" frontend. It opens up some security holes (right now we're dealing with potentially insecure file privileged levels in Samba, and potential vulnerabilities in the three daemons that are running) by making you take into account the webserver, possibly PHP, the scripts on the server, and the database server. Besides, web front-ends to fileservers just suck. Who wants to upload their entire music library one song at a time? If you really want something like this, I advise just setting up a simple forum or something like that to discuss the server and/or contents, and possibly to provide a WebDAV interface to the files on it.
  • Icecast would also be nice, and might be a reason to provide a web interface. Icecast is a streaming server, so it'll allow people to listen to a stream of a playlist or maybe queue up tracks using a browser. This might be handy for those using music clients that don't support daap.
  • You'll probably also want to give a few people shell access, so just install openssh and do whatever you need to configure it (you might need to rename a file, but that's the most -- it'll be the simplest out of the five above). SSH is always handy, and you'll need it anyway to configure your server remotely.

The first two are the only truly vital ones. SSH is vital in a different sense, but you definitely should have it. It almost isn't optional. Rsync and HTTP/WebDAV are just icing on the cake. Rsync is the one I would rather spend time on, though, as it's infinitely more powerful and useful than an httpd. Icecast is nice to have, but since you have samba and daap, not really needed.

Since you're potentially running afoul of copyright law, I would encrypt the server's filesystems at the root level. This would mean you'd have to do some extra and potentially tricky configuration while installing Gentoo (and this is the one area where Ubuntu is better -- it just has an installer option for this), but thankfully it's all documented at the Gentoo Wiki. This is the guide I used for my servers, and it works great. Crypto is a very very good thing and since you might be a target, you should definitely use it. Better to be safe than sorry.

Good luck with this. Aim high with your goals, because they're all reachable with enough googling and there's nothing better than setting up a well-running server. If you're anything like me, you'll have loads of fun while doing it, as well.

EDIT: if you must use Ubuntu, all the stuff I mentioned is in the Ubuntu repos, so it won't be difficult at all to install. Using Ubuntu will make your server a bit bloated, though, and again, I highly recommend Gentoo.
