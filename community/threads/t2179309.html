Okay, see that last post in that thread? That's damn wrong.

There is always a reason. Nothing on a computer happens for "no reason".

It's extremely unlikely that adding anything in some source code header file changed anything, and I wouldn't do that in the future. Do this:

  1. Remove the drive safely in windows and turn it off.
  2. Boot into Ubuntu and open up System>Administration>System log
  3. Turn on the drive and read the new log entries. Copy and paste them here and to ubuntuforums.

Assuming the drive is ntfs, it's probable that what's happening is that it's marked as dirty, and as such you'd have to manually mount it in Ubuntu. Note also that I doubt fdisk would list the drive, as it's an external.

Get back to us with the logs. They will either contain messages pertinent to your success, or contain errors that we can then debug.

fdisk will list any drive, whether it has partitions or not.. and regardless if they are mounted, not CD/DVD drives.. but you get the idea.

In this case if he plugs the device in, fdisk isn't showing anything either because of permissions, say he is running fdisk as UID 500 for example, and udev created the device rwx------ for user root, he wouldn't see anything from fdisk, or the device needs to be plugged into the wall, I've seen many different configurations for external devices and sometimes it was a simple modification of udev rules that was neccessary for using the device as anyone but root.
