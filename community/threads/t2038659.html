Sorry about the downtime
Sorry about the downtime. I've been spending every night when I got home from work and most of last weekend trying to figure out why the site was slowing to a crawl every time I enabled it.

It turns out there were a couple of culprits:

The Porn Thread (http://www.totse.com/community/showthread.php?t=1803001) is being linked to by the outside world. Because it's such a long thread MySQL has to retrieve thousands of records every time someone brings up ONE of the pages in the thread. The load of thousands of people hitting this one thread was killing the system.

The Shoplifting Thread (http://www.totse.com/community/showthread.php?t=1733650) is also getting a large number of hits.

For now the best thing you can do is to split large threads up into multiple smaller threads (10 pages or fewer). If you see a thread getting large, close it, sticky it, and open a new one (Part 2, or 8 as the case may be).

I'm looking at installing more memory and using Squid to cache pages, which should take a large load off the database, especially in cases where a thread is hugely popular. In the meantime, try to keep threads to less than 10 pages.

Re: Sorry about the downtime
One other thing that was causing a problem:

It turned out that the server that I use for primary DNS was down (and I didn't know about it), and MySQL actually uses DNS for some operations unless you tell it not to. So:
Queries would hit MySQL.
MySQL would do a DNS lookup to validate where the query came from.
Since primary DNS was down, it would just sit until primary timed out before trying secondary DNS.
A bunch of these queries would pile up and eventually Apache would run out of server processes, bringing the whole site down.Primary DNS is back on-line and I've added a directive to MySQL's startup so it doesn't use DNS any more.
