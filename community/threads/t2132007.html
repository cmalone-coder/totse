Auto downloader, possible?
OK, I've got a huge plan
I've just bought 2 servers, as a few of you may already know, and after being told I practically cannot use them as web servers I have come up with a new idea:
I don't think I need to split the two jobs to the two servers, but it'd probably make it quicker.
First Server: I'd provide it with 10-20 artists/bands that I like. Then it will search these (iTunes store, The Pirate Bay, Youtube etc) and provide the second server with a list of song names from the "Recommended Tracks", "Other people bought this", "Related Videos" etc.
Second Server: Reads the file that the 1st server sends to it and then connects to Limewire network (Gnutella, or whatever it's called) and searches automatically these song names.
I understand that,
1. I will need lots of harddrive space
2. I will get tons of malware/viruses/porn etc
3. I may get a letter from my ISP because of piracy/bandwidth

In relation to no. 3, I may proxy (possibly with an automatic proxy updater as well).

This will be hard, I understand that. But I have 2 servers, a decent amount of money and 13 weeks of summer holiday

Problem is, I have no idea where to begin. Right now, the only programming language I know is Python (Does PHP count?).

Any tips/suggestions/"don't bother"s?
Cheers.

EDIT: I also know that half of the songs it downloads will be the same or adverts or just shit that I don't want.. the point is I will be downloading so much that the small percentage I get that I do want will be enough to make it worth all the crap.

Re: Auto downloader, possible?
C#. Problem solved.
  • Use a WebClient object to search for various artists/tracks on the web
  • Use a Regex object to parse the returned information
  • Use remoting or a Socket object to send this information to your second server
  • Use a Socket object to search and download the files from Gnutella
C# is easy enough to learn. But if you ONLY know Python, I'm going to recommend that you learn C and some Assembly for your own benefit, as well as C++.
