Your use of $newfile is incorrect.

When you set it to "headers/" . $email . ".txt" you should instead set it to: "/home/username/path/to/headers/" . $email . ".txt"

If you don't know the path to the headers folder, navigate there from the command line (or ftp) and issue the command "pwd" (print working directory).

Code:
bash-3.1$ ls test/

email.txt

bash-3.1$ ls /home/zok/test/

email.txt
Notice how /home/zok/test and test/ are the same thing? That works here. But if I were to navigate to... /home/notzok and run "ls test/" it would instead tell me "ls: cannot access test: No such file or directory" - why? Because "header/" and "test/" are relative in comparison to the script. If you supply the full path beginning with a /, it assumes that it's an absolute path.

Analogy time: Question: "Where is ohio?" Answer 1: "North" Answer 2: "Latitude 38° 24′ N to 41° 59′ N - Longitude 80° 31′ W to 84° 49′ W" Answer 1 will only be correct some of the time - it depends on where you are. Answer 2 will always be correct - regardless of where you are.

When your cron script runs, it is not running your script from the script's location on the computer - instead cron runs it from its own area on the computer (I don't know where or how). The problem is that it's looking for a directory called "headers" there. If you give it the absolute path, it can't make a mistake because you're telling it exactly where your "headers/" directory is.

Does that make sense?
