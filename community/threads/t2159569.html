I've had similar problems, the Intel HDA and intel iwl3945 are very crapy drivers. And companies aren't helping, at all. I've had countless problems with both
They try so hard to hide what is the true chipset of your card/s.

Anyway, look if you have the latest version of alsa, if you don't, upgrade (from source). If it's still not working, downgrade. If you hopelessely can't get it to work, the FreeBSD Intel HDA is way more stable.
See if your wireless card is supported and install either DesktopBSD or PC-BSD.

Edit: Is there a software switch for the **speakers? it could very well be the problem.

I've run into problems like these before, universally on shitty laptops with cheap shitty software-driven sound "hardware" (think the old "Winmodems" that had to handle all of their data processing via the system processor, back in the Windows 98 days) that doesn't have a physical leaf switch in the headphone jack but instead relies on a software switch to send the signal to the headphone jack or speakers.

I have a friend with a Sony Vaio laptop that had the identical problem but in reverse. His speakers worked, but if you plugged in headphones nothing would happen. Pretty sure that thing also had a bottom-of-the-barrel Intel audio chipset. We found a lot of guides and forum posts about config file fiddling and various options to add and none of the advice in them worked.

Eventually he upgraded to Ubuntu Hardy Heron (8.04) and like magic the headphone jack started working. Whatever config file change happened between Gutsy and Hardy apparently did the trick. We may never know what the hell it was, though.
