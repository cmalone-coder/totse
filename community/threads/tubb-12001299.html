Re: Open Source DOS router/gateway
I will try an answer what I can. Off the top of my head, I can give you answers to some of the questions but not all, bear with me:


1.
quote:
I do have DOS compatable drivers for the CD-rom. How would I get those onto the bootdisk, so that they load with the OS and run?


Assumption: FreeDOS uses Autoexec.bat and Config.sys files.

Response: In this case I would try and get the DOS drivers and load them a start time by adding appropriate entries into autoexec.bat and config.sys. Here are my old autoexec.bat and config.sys files from MSDOS:

[code=autoexec.bat]a:\mscdex /d:MTMIDE01[/code]
[code=config.sys]DEVICE C:\MTM\MTMCDAI.SYS /D:MTMIDE01[/code]

I could be wrong.

2.
quote:
How would I find the neccessary .com drivers? And how do I get the computer to recognise two separate instances of the same drivers, and their associated hardware.


Search for the Vendor and Model of your PCMCIA cards online with a google search and see if you can find DOS drivers.

+Vendor +Model +DOS +driver

I believe that the cards would be destiguished to the PC via differing I/O and IRQ addresses. The only problem might be you identifying or resolving how FreeDOS will deal with 2 NICs.

3.
quote:
how difficult would it be to write a basic DOS firewall which block by default ALL traffic on all ports. The user than defines exacltly which ports are open and which are not.


Depending on what you want your firewall to protect against. Firewall function is basic, you will write code that examines data attempting to move from the data-link layer (MAC) into the network layer (IP). Programming wize, I would say it would be a decent challange if you are not used to network programming, and depending on the Application Programming Interface (API) you have to work with, it could either be easy, or a total mess.

4.
quote:
Can this firewall open and close ports dynmamically based upon whether or not they are in use?


That is called either a reflexsive firewall or in a more advanced state, a content filterning firewall. A reflexsive system works by allow all but specifically blocked traffic out, while only allowing data back in that is part of a "session". You determine this by looking at the ACK and RST bits in the TCP headers, thus this only works at keeping out TCP traffic, any other traffic will not be allowed back in (ICMP, UDP, IPX).

5.
quote:
Finally can this firewall be accessed, and changed via a remote command prompt from inside the LAN without compromising the external wall?


You could do this by using authentication and dynamic firewalling. You can use an authentication scheme (RADIUS) to authenticate you from anywhere on the net and allow connections from your location into the network/server. This of course, is getting more advanced.

Another options, which I doubt is even one for you, is dialup console access. I don't know if FreeDOS does any of this stuff. Plus, to make dialup connections secure, you must setup "call back".


Phew.

To finish off: There must be a good reason that you are trying to do all of this with FreeDOS? Linux will do all of this very well, except for content filtering... In my opinion it would be a much better route to go. You also have many other unix variants that apply well to this role. NetBSD, OpenBSD, FreeBSD.
