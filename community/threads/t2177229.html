#2

Prometheum
Regular

Add /usr/bin/firefox to your $PATH variable. When you type a program name into the shell, it searches the folders in that variable and stops when it hits the first one. Typically, it looks like this:

/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games

Possibly different. That's my Ubuntu system, this is my Gentoo system:

/usr/local/bin:/usr/bin:/bin:/opt/bin:/usr/i686-pc-linux-gnu/gcc-bin/4.1.2

This is my FreeBSD system:

/sbin:/bin:/usr/sbin:/usr/bin:/usr/games:/usr/local/sbin:/usr/local/bin:/usr/X11R6/bin:/home/*****/bin

What you need to do is add a line like

Code:
export $PATH = "/usr/bin/firefox:$PATH"
in your .bashrc.

A slightly more braindead but perhaps less annoying way to do it might be just to create a symlink to /usr/bin/firefox/firefox called "firefox." Just stick it somewhere that's in your collection of $PATH places, like /usr/bin. Done.

That way you don't have to keep track of whatever gack you've had to add to your path variable, especially if you find yourself executing many programs from nonstandard locations.

Back when I started messing with Linux I made a symlink to ls called "dir," for when my ingrained DOS reflexes got the better of me.

Actually instead of modifying your path for any particular purpose, like executing a single command, instead of having access to many binaries or shell scripts, you can set an alias.

Look at the alias manual page, it is part of /bin/bash:

Quote:
alias [-p] [name[=value] ...]
Alias with no arguments or with the -p option prints the list of
aliases in the form alias name=value on standard output. When
arguments are supplied, an alias is defined for each name whose
value is given. A trailing space in value causes the next word
to be checked for alias substitution when the alias is expanded.
For each name in the argument list for which no value is sup-
plied, the name and value of the alias is printed. Alias
returns true unless a name is given for which no alias has been
defined.
