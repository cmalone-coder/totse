....I have only read a few pages, and already it was talking about the command line and some general commands.

You can always get a book specific to the command line

Also though, books can only take you so far as well. Set up a linux and try to solve the problems that arise, no doubt there will be problems. Google the problem, check the documentation (making sure you understand), then solve the problem. Then move on to the next. I think this practice is very important in actual learning.

I give you one of my own examples...

Recently i set up ubuntu linux on my laptop, (i myself am fairly new to linux and wanted to install for more in dept learning)...RIght away it wouldn't even load, a few hours later i found out it was an acpi issue. I turn it off editing the boot sequence. Then i proceeded to install ubuntu, after install, once again it wouldn't load. This time i had to configure the grub menu.lst. I did that, now it boots up perfectly. As soon as i hit the desktop, my resolution was 800x600. I have 1024 x768 display. So in gnome there is a utility that allows you to change the resolution and 1024x768 didn't even show up. So i had to configure the xorg.conf file, i did that, set it to higher resolution and it's works perfectly.Then i noticed on my laptop that the touch pad mouse control was way too sensitive. I couldn't even move it without it clicking everything in my browser. So once again, i had to go back into xorg.conf change the MaxTapTime setting, now it works perfectly.

I have to say i must of learned more in a few hours on that day about linux, than i did with half a year with suse.

Hello rabbitweed,

Abandoning Ubuntu GNU/Linux for a another more advanced Linux distribution will be a very progressive decision on your behalf. As you probably know, Ubuntu was designed to introduce the average computer user a viable alternative free operating system (rather than to Linux its self, and as compared to Microsoft's Windows OS's and OS X).

This is an interesting endeavor; however, the path to your intellectual progression in the direction of Linux is not as significant of the matter of your distribution of choice, but rather what you literally -- "do on it" as villageillness strongly pointed out.

I do not know you personally, so I couldn't give you the best advice of my ability beyond providing some ideas that you might be interested in as well as give you some motivation toward achieving your goal of Linux "nerdiness".

How about setting up an IRC daemon on your Linux machine (Search Unreal ircd), an eggdrop bot, manually installing and configuring sshd/httpd/mysqld/ftpd/etc., and play with iptables. There's a million things you can do with a home web server, including phpbb, webalizer, phpmyadmin, blogging, etc. Do you use AIM/MSN/YIM/IRC/ICQ? Check out bitlbee. You could pick up some tutorials on writing scripts for X-Chat in C, Python, TCL, and Perl. Check out KDevelop and visit some tutorials on programming. It's slow and boring at first, but once you get to socket programming the real fun starts. Alternatively, you can use vi or nano with gcc.

Compiling on CLI environment based platforms is easy and most of the time with normal software installations, only requires three commands.

Slackware is a great distribution and I recommend it. Here's a rundown of a few entry to intermediate flavors that I also recommend:

1. Fedora and CentOS - Both are Red Hat based. Fedora is bleeding edge and CentOS is a very stable clone of RHEL. I find these two the easiest to fix and hardest to render to the point of a required reinstall.

2. Debian - Ubuntu is based on Debian. It's pretty solid and has a great supportive community for any and all of the questions you might have. In a nutshell, Debian is like Ubuntu, but without the "n00bness."

3. Gentoo - For a learning experience, Gentoo surely provides you with insight. It's a bit more advanced and you're almost forced to read the installation documentation if you're an introductory Linux user. It's a fun distribution but easy to destroy by accident.
