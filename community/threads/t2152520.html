This isn't an fstab problem, it's a problem with whatever NFS system you're using (actual NFS, samba, etc.)

What are you using, and how did you change the permissions in the beginning? Remember, you might not be able to change it from client, regardless of your permissions.

(If I remember correctly, you're using samba, so) Check samba's config files and see if it's a problem there, then see if you're fully authenticated on the remote host. File permissions won't matter if Samba's blocking write access.

What filesystem is the harddrive running?

If it's an external, if it's using FAT32 or NTFS, it's quite possibly just a file system bug. I kept thinking internal. Yeah, fstab wouldn't give any info unless you manually added the UUID in there.
Other than that, I suggest you get a live-cd and try to write to it that way. It could be corrupted.

I think I would do the following

1. make sure it's not corrupt
2. make sure you can read from it
3. find a way (anyway) to write to it

If you can write to it, then it's good for working.

Now that you have established it works, check the various programs and protocols that allow you to share it.
This is why every techie needs two computers. I'm a firm believer in that these days.

Connect both boxes and try to share files.
If you can't then check the files that are part of the programs, that allow you to share.
Something isn't set correctly.
One last trick is to uninstall the application and reinstall it.
Corruption of a program isn't common, but I've had it happen to me before.
